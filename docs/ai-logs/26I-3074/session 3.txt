How Validation & State Work

  
Centralized formState (contact.js):
  
  

  
values: Stores the current values of name, email, and message.

  
touched: Tracks whether each field has been interacted with (blur or non-empty input), preventing premature empty-field errors on untouched fields.

  
hasAttemptedSubmit: Flips to true when Send is clicked so every field—even untouched empty ones—shows validation feedback.

  
errors: Holds the current error message per field ("" when valid).

  
lastSubmitted: Stores { name, email, message } after a valid submission to drive the local #contact-confirmation banner.

  

  
Pure Validator Rules (contact.js):
  
  

  
validateName: Rejects empty strings and names shorter than MIN_NAME_LENGTH (2 trimmed characters).

  
validateEmail: Rejects empty strings and formats failing EMAIL_PATTERN (/^[^\s@]+@[^\s@]+\.[^\s@]+$/).

  
validateMessage: Rejects empty strings and messages shorter than MIN_MESSAGE_LENGTH (10 trimmed characters), displaying progress like (4/10).

  

  
Live Validation (input & blur):
  
  

  
On input, formState.values[fieldKey] updates, updateMessageCounter() refreshes the live character count (0 / 10 min → N characters), any prior confirmation banner is cleared if the user starts composing a new message, and renderFieldState() validates immediately if the field has content, was previously touched, or submit was attempted.

  
On blur, formState.touched[fieldKey] becomes true and renderFieldState() runs so leaving a required field empty displays its error right away.

  
renderFieldState() toggles .is-invalid / .is-valid, sets or clears aria-invalid="true", and writes the message to the field's role="alert" error element.

  

  
Submit-Time Validation & Local Confirmation (contact.js):
  
  

  
submit calls event.preventDefault(), marks all fields touched, validates all three fields, and focuses the first invalid input if any error exists.

  
When all fields are valid, it saves the summary into formState.lastSubmitted, resets the form (form.reset() and resetValidationState()), reveals #contact-confirmation with a personalized thank-you message and dismiss button, and triggers #status-toast.

  

  
Responsive Layout (crumb-pages.css):
  
  

  
Desktop renders .contact-layout as a 2-column horizontal grid (0.95fr 1.05fr).

  
At max-width: 960px, .contact-layout stacks into a single vertical column (1fr).

  
At max-width: 720px and 640px, the desktop navbar switches to the mobile #menu-toggle drawer and card padding tightens for mobile screens.
